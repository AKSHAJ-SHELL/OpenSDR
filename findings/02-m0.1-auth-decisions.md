## M0.1 — Authentication & authorization: decisions & gate notes

**Status:** implemented on branch `m0.1-auth`; tests green (90 passed, 0 skipped, Postgres up).
**Plan:** `plans/m0.1-auth.md`. **Closes:** finding A1.

### What shipped
- Scoped API-key auth on every route except `/health` and `/u/{token}`. Keys are
  `csk_` + 32 url-safe random bytes, stored only as SHA-256; scopes `read ⊂ operate ⊂ admin`.
  `craftsman/api/auth.py` (`require_scope`), wired per-route across all six routers.
- Key management: `POST/GET/DELETE /keys` (admin), soft-revoke via `revoked_at`.
  Bootstrap CLI: `python -m craftsman.create_key --name … --scopes …`.
- `/docs` + `/openapi.json` gated behind `read` (custom routes replace the built-ins).
- Dashboard: scrypt password login (`DASHBOARD_PASSWORD_HASH`), HMAC-signed httpOnly
  session cookie, Next 16 `proxy.ts` redirect gate, and a session-gated `/api/proxy/[...path]`
  that forwards to the API with a server-held key — **the key never reaches the browser**
  (verified live: absent from page HTML and proxy bodies).
- Tests: `tests/unit/test_auth_unit.py`, `tests/e2e/test_auth_integration.py`,
  `tests/adversarial/test_auth_attacks.py`. Includes a fail-closed route audit that 401s
  every non-allowlisted endpoint (a new unauthenticated route breaks CI by construction).

### Decisions the human approved (2026-07-20)
1. Scope hierarchy `admin ⊃ operate ⊃ read`.
2. Campaign create / variant add / CSV import = `operate` (the dashboard's role).
3. Hashed dashboard password.
4. `/docs` not publicly exposed → gated behind `read`.

### Deviations from the approved plan (please confirm at the gate)
- **scrypt, not bcrypt.** The plan named bcrypt; I used Node's built-in `crypto.scryptSync`
  instead. Reason: it adds **zero npm dependencies** (bcryptjs would need install + a
  package.json change, which the working agreement says to ask about), and it's a strong,
  salted KDF. Verified constant-time via `timingSafeEqual`. Format: `scrypt$salt$hash`.
- **No Alembic migration yet.** Per the plan, the `api_keys` table rides `create_all` for
  now and will be captured in M0.2's baseline migration (M0.2 is the Alembic epic).
- **`/docs` behavior:** because a browser can't attach a Bearer header on page load, a bare
  visit to `/docs` returns 401. Interactive use = fetch `/openapi.json` with a key into an
  OpenAPI viewer. The gate's real job is closing surface enumeration on `/openapi.json`.

### Gate questions for the human
- Confirm scrypt is acceptable in place of bcrypt (above).
- `docker compose up` now **requires** `CRAFTSMAN_API_KEY`, `DASHBOARD_PASSWORD_HASH`,
  `DASHBOARD_SESSION_SECRET` (compose fails loudly if unset). This is a deliberate,
  documented change to the "one command" story — acceptable?
- Suppression/erase and mailbox routes are `admin`; the dashboard key is `read`+`operate`,
  so erase/mailbox management is intentionally **not** doable from the dashboard yet
  (those UIs land in M1.3). Confirm that's the intended posture for now.
