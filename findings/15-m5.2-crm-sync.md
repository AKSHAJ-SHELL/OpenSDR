## Deviations from the roadmap text (with rationale)

1. **"Field mapping UI" is default-map + overlay, not arbitrary-property
   discovery** — the map targets the fixed `LeadRow` vocabulary; unknown
   targets 422. Discovering the CRM's full property schema is provider-API
   surface with no consumer yet.
2. **Enrollment ("lists → mapped to campaigns") goes through the ONE
   enrollment path**: the activate loop was extracted verbatim to
   `scoring/enroll.py` and CRM import calls it for the already-verified
   subset only. Fresh imports verify first (async) and enroll on the
   campaign's next activate — the ICP gate is never bypassed for CRM leads,
   and unverified leads are never scored on empty fields.
3. **Outbound sync is at-most-once, not at-least-once**: the watermark
   advances even when individual pushes fail (tallied on the run). A poisoned
   record retried forever against a rate-limited CRM API is the worse
   failure mode; the run record keeps it honest.
4. **Salesforce "lists" are Campaigns** (members = Contacts AND Leads, both
   imported with `remote_type` preserved for the activity WhoId). Reports
   would need the Analytics API — out of scope, documented.
5. **Conflict doctrine implemented narrowly**: CRM-wins covers exactly
   `CRM_OWNED_LEAD_FIELDS` (first/last/title/linkedin/timezone); email is an
   identity, company fields flow only at create-time via the ingest gate, and
   a blank CRM field never clears a lead field.

## Known gaps / open items

1. **Both adapters are stub/MockTransport-tested only** — no live HubSpot
   portal or Salesforce org was touched this session. The request shapes
   follow current public API docs (HubSpot v3 lists/objects + fixed
   association type ids 200/202; Salesforce v59 SOQL/sobjects +
   client-credentials flow), but the first live connect/import/push is
   UNVERIFIED, same status as OIDC after M5.1.
2. **HubSpot private-app tokens and Salesforce client secrets don't rotate
   automatically** — PATCH credentials is the rotation path; documented, not
   automated.
3. **Inbound is pull-on-demand only** — no scheduled re-import, no CRM-side
   webhook listener. Deliberate: ambient contact pulls move customer data on
   a timer nobody asked for; a fork can add a beat task in ~20 lines on the
   existing seams.
4. **Activity push truncates bodies at 2000 chars** and doesn't push
   touch-task (LinkedIn/call) activity — only sends, classified replies, and
   meetings. Extension point is `collect_activity`.
5. **`crm_sync_tick` interval is fixed** (900s in `celery_app.py`), not a
   config knob — matches the other beat entries' style.
