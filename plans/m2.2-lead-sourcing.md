## Goal

Let an operator **find** leads, not just upload them. A `LeadSourceProvider` protocol
turns an ICP query + filters into candidate people from **your own** provider account
(Apollo, or a generic webhook feed) — then routes every candidate through the *exact same
import gate* a CSV goes through: syntax → dedupe → suppression, **zero shortcuts**. The
dashboard gets a "Find leads" page: search → preview with honest per-candidate labels →
import selected. No proprietary database, no pretending otherwise — results are branded
with the provider they came from.

This is the acquisition half of M2 (M2.1 enriched leads that already existed; M2.2 brings
new ones in). Sourced leads land exactly where CSV leads land — `status="new"`, enqueued
for verify → enrich (the M2.1 chain) — so everything downstream is unchanged.

## Current state (verified in code)

- **The import gate lives inside `import_csv`** (`ingest/csv_import.py:35-93`): it collects
  emails, batch-queries existing `leads` + `suppression_list`, then per row runs
  `syntax_ok` → dedupe (in-batch `seen` + existing) → suppression → get-or-create Company
  by domain → create `Lead(source="csv")`. Returns `ImportResult{imported, deduped,

- **Enrichment enqueue is in the router, not the gate.** `api/routers/leads.py:24-31`

  path must do the same (sourced leads must verify+enrich too).
- **Apollo already has a key + a `_fetch` seam pattern** from M2.1 (`ingest/enrichment.py`
  `ApolloProvider`). `apollo_api_key` config exists. Sourcing is a *different Apollo
  endpoint* (`mixed_people/search`) but the same BYO-key + monkeypatch-seam shape.
- **The SSRF-guarded fetcher is ready for a webhook source.** `research/fetch.py:67`
  `validate_url` enforces https-only + `ALLOWED_PORTS={443}` + rejects any host resolving
  to a private/loopback IP (every redirect hop re-checked). A webhook source URL must pass

- **Dashboard patterns exist.** `Sidebar.tsx` is a flat `NAV` array; `LeadImport.tsx` is
  the reference client component that POSTs through the session-gated proxy

## Design

### 1. Extract the shared gate — `ingest_leads(...)` in `ingest/gate.py` (new)

```python
    title: str | None = None

    # batch-load existing+suppressed once, then per row: classify → persist if new.
    # returns (result, new_lead_ids) so the caller enqueues verify/enrich.
```

`import_csv` becomes: parse CSV → normalize columns (its existing `COLUMN_ALIASES`) →
`list[LeadRow]` → `ingest_leads(db, rows, source="csv")`. **Behavior byte-for-byte
identical** — the existing CSV tests are the regression guard (they must stay green
untouched). The gate returning `new_lead_ids` lets both routers enqueue `enrich_lead`
from one place instead of re-querying `status="new"` (a small, safe improvement that also
fixes a latent bug: the current re-query enqueues *every* `new` lead in the table, not
just this import's — noted, fixed by threading ids through).

### 2. Provider protocol — `ingest/sourcing.py` (new)

```python
@dataclass(frozen=True)
class SourceQuery:
    icp_query: str = ""            # free-text ICP description
    titles: list[str] = ()         # structured filters (provider maps what it supports)
    seniorities: list[str] = ()
    industries: list[str] = ()
    locations: list[str] = ()
    company_domains: list[str] = ()
    employee_ranges: list[str] = () # e.g. "51,200"
    limit: int = 25                # hard-capped (see §5) to bound provider spend

class LeadSourceProvider(Protocol):
    name: str
    async def search(self, query: SourceQuery) -> list[LeadRow]: ...
```

- **`ApolloSourceProvider`** — `POST /api/v1/mixed_people/search` (BYO `apollo_api_key`),
  maps `SourceQuery` → Apollo params (`person_titles`, `person_seniorities`,
  `organization_industry_tag_ids`→ we pass `q_organization_...` text filters honestly,
  `organization_num_employees_ranges`, `person_locations`, `q_keywords`←icp_query). One
  `_fetch` seam. **Honesty note baked in:** Apollo search often returns people whose email
  is *locked* behind credits (`email_status` set, `email` a placeholder like
  `email_not_unlocked@domain.com`). The provider emits the candidate **with whatever email
  Apollo gave**; it does **not** fabricate one. Locked placeholders then fail the gate's
  `syntax_ok`/real-domain check and surface as `invalid` in preview — the operator sees
  "Apollo has this person but not a usable email," never a silent bad import. (This is the
  ToS-honest behavior; the alternative — auto-spending unlock credits — is not done
  silently.)
- **`WebhookSourceProvider`** — GETs `lead_source_webhook_url` (query filters appended as
  params) **through `validate_url`** (SSRF guard), parses a JSON array of lead objects (or
  `text/csv` body via the same column-alias normalizer) → `list[LeadRow]`. For operators
  whose lead source is their own system/feed. https-only, private-IP-blocked, by reuse.
- **`NullSourceProvider`** — returns `[]`. The honest "no source configured" default.

`build_source_provider(settings, name) -> LeadSourceProvider | None`: returns the named
provider only if it's in `lead_source_providers` **and** its key/URL is present; else None
(endpoint 400s with a clear "provider not configured" message). Mirrors M2.1's
`build_enrichment_chain` discipline.

### 4. API — two endpoints (`api/routers/leads.py`)

The roadmap's "`POST /leads/source` runs search → dedupe → import" is split into a
**preview** and a **commit** to honor the page's "preview → import selected" UX — together
they *are* search → dedupe → import through the existing gate:

- **`POST /leads/source`** (scope `operate`) — body `SourceSearchRequest{provider, query,
  filters, limit}`. Runs `provider.search()`, then **read-only** annotates each candidate
  via `classify_row` against current leads + suppression → returns
  `SourcedPreview{provider, candidates: [{row fields..., status}]}`. **No writes.** Honest
  labeling: response carries the provider name for branding.
- **`POST /leads/source/import`** (scope `operate`) — body `SourceImportRequest{source,
  leads: [selected rows]}` → `ingest_leads(db, rows, source)` → enqueue `enrich_lead` for
  the returned new ids → `ImportResult`. The gate re-runs **every** check (the client is
  untrusted — a hand-crafted request to import a suppressed address is rejected here, not
  just hidden in preview). This is the "zero shortcuts" guarantee, enforced server-side.

Schemas: `SourceSearchRequest`, `SourceFilters`, `SourcedCandidate` (LeadRow + `status`),
`SourcedPreview`, `SourceImportRequest` in `core/schemas.py`.

### 5. Guardrails

- `limit` clamped to `≤ 50` (bounds provider spend; same spirit as dry-run's `n ≤ 10`).
- Preview and import both cap the candidate list length server-side.
- Webhook responses capped (reuse a size bound) so a hostile feed can't OOM the worker.
- Every provider call is failure-isolated: a provider raising → 502 with the provider's
  message surfaced, never a 500 stack leak; a webhook SSRF rejection → clear 400.

### 6. Web — `/find-leads` page (new) + sidebar entry

Client component (form + selection + two POSTs, like the builder):
- **Search form:** provider select (only configured ones), free-text ICP query, structured
  filter inputs (titles, seniorities, industries, locations, employee range, limit).
- **Preview table:** one row per candidate with a **status badge** — `new` (checkable,
  checked by default), `duplicate`/`suppressed`/`invalid` (shown, greyed, not importable,
  with the reason). Honest count summary ("18 new · 4 duplicates · 2 suppressed · 1 no
  email").
- **Import selected** → `POST /leads/source/import` with the checked rows → `ImportResult`
  banner → link to Leads.
- **Provider branding banner:** "Results come from your **{Provider}** account." Empty
  state when `lead_source_providers` is unset: how to configure, no fake data.
- Sidebar gains **Find leads** (after Leads). Reuses `Badge`, `PageHeader`, `EmptyState`.

## Out of scope (named so it isn't mistaken for missing)

- **Intent signals & the scoring reweight** — M2.3 (and the ⛔ Gate M2 item). M2.2 sources
  and imports; it does not score or auto-enroll.
- **New source providers beyond Apollo/webhook** (LinkedIn, ZoomInfo, Clay…) — the
  protocol makes them cheap later; M2.2 ships the two the roadmap names + `null`.
- **Auto-unlocking Apollo emails via credits** — deliberately not silent; a later opt-in
  could add it behind an explicit, budgeted flag.
- **Saved searches / scheduled sourcing** — a Celery-beat sourcing loop belongs with M2.3's
  signal collectors, not here.
