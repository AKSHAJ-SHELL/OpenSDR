## Shape

```
craftsman/crm/
  provider.py        CRMProvider protocol + CRMContact/CRMActivity/CRMListRef
                     dataclasses. Source-agnostic, like ingest/gate.LeadRow.
  hubspot_impl.py    Private-app token. Contacts search/lists, timeline notes,
                     meetings. api.hubapi.com only.
  salesforce_impl.py OAuth2 client-credentials against the org's my-domain
                     token endpoint; Contact/Lead SOQL, Task/Event sobjects.
  mapping.py         Field mapping: per-connection JSONB overlay on a default
                     map; apply + dry-run diff preview. CRM wins contact
                     fields; Craftsman wins engagement history (roadmap text).
  sync.py            import_from_crm (list → LeadRow batch → ingest_leads,
                     source="crm:<provider>") and push_activity (send/reply/
                     classification/meeting → timeline; meetings → CRM events).
```

- **Models (migration 0019):** `CRMConnection` (OrgScoped; provider,
  Fernet-encrypted credentials like mailbox passwords, field_map JSONB,
  active), `CRMLink` (OrgScoped; connection_id + lead_id ↔ remote contact id;
  UNIQUE per (connection, lead) and (connection, remote_id)), `CRMSyncRun`
  (OrgScoped; direction, counts, status, error) — every import/push leaves an
  auditable run row.
- **API (`/crm`):** connection CRUD (credentials write-only — never echoed),
  `POST /crm/connections/{id}/test`, `POST .../import` with `dry_run` (default
  true → preview of mapped rows + field-map diff, no writes) and
  `campaign_id` mapping, `GET .../runs`. Admin scope for credential writes,
  operate for import/sync.
- **Worker:** `crm_sync_tick` beat task (per-org, per-connection) pushes
  activity newer than the connection watermark; failures dead-letter per
  house pattern. Import stays request-triggered (a human maps list →
  campaign; no ambient contact pulls).
- **Tenancy:** connections/links/runs are OrgScoped — the M5.1 layer does the
  isolation; adversarial tests prove it anyway.
- **SSRF:** HubSpot host is fixed. The Salesforce instance URL is
  operator-supplied and fetched server-side → validated with the same guard
  webhooks use, at write AND use time.
- **Web:** connections page + field-mapping UI with dry-run preview table
  (delegated to a subagent against the finished API, like M5.1b web).

## Tests (predict-then-run where adversarial)

- unit: mapping apply/diff, both providers' parsing + auth via
  `httpx.MockTransport` (no live network, LLM_PROVIDER=mock).
- e2e: connection lifecycle with credential redaction; dry-run preview vs
  committed import (dedupe/suppression respected — reuses the M2 gate);
  activity push writes through a stub provider; sync-run bookkeeping.
- adversarial: cross-org connection/link/run isolation (extends the
  isolation suite pattern); forged org_id in connection payloads; credentials
  never in any response body; suppressed lead in CRM list stays suppressed;
  import into a foreign campaign 404s.

## Non-goals

- No bidirectional field write-back to the CRM beyond activity/events (contact
  field edits flow CRM→Craftsman only, per the source-of-truth doctrine).
- No OAuth authorization-code dance for HubSpot (private-app token is the
  self-hoster path; documented).
- Pipedrive/Zoho/etc. — the protocol is the extension point, forks add
  adapters.
