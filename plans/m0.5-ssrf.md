# Plan — Epic M0.5: SSRF guard on research fetch (A2)

**Branch:** `m0.1-auth` (M0 line) · **Status:** awaiting approval · **Roadmap:** M0.5 · **Finding:** A2

## Goal

The research fetcher can no longer be aimed at internal infrastructure. A crafted CSV
row (`company_domain`) or a redirect must not let `research/fetch.py` reach
`169.254.169.254` (cloud metadata), `localhost:6379` (Redis), `file://`, or any
private/loopback/link-local address. https-only, public-IP-only, bounded redirects.

## Current state (verified in code)

- `craftsman/ingest/csv_import.py:69` takes `company_domain` from the CSV verbatim
  (only `.strip().lower()`), stores it on `Company.domain`.
- `craftsman/research/fetch.py:37` builds `url = f"https://{domain}{path}"` and GETs it
  with `follow_redirects=True`, `timeout=15`, **no scheme/host/IP/port checks**. Every
  attack in the finding works today:
  - `domain = "169.254.169.254"` → `https://169.254.169.254/` (metadata over TLS/plain)
  - `domain = "localhost:6379"` → `https://localhost:6379/` (host-local Redis)
  - `domain = "[::1]"`, `"10.0.0.5"`, `"192.168.1.1"` → internal hosts
  - `domain = "evil.com"` returning `302 → http://169.254.169.254/` → followed blindly
- The fetched text flows only into the grounded copywriter (the validator still gates
  outbound), so the realistic damage is **read-SSRF / port-probing / metadata theft**,
  not outbound content injection — but metadata theft (cloud creds) is severe on its own.

## Design (all in `craftsman/research/fetch.py`; no schema, no API change)

### 1. URL validation (`validate_url(url)` → raises `UnsafeURL`)

- **Scheme allowlist:** `https` only. `http`, `file`, `ftp`, `gopher`, `data` → reject.
- **Port allowlist:** default (none) or `443` only → kills `localhost:6379` and friends.
- **Host → IP check:**
  - if the host is an IP literal, validate it directly;
  - otherwise resolve via `getaddrinfo` and require **every** returned A/AAAA record to
    be public. Any private result rejects the whole host (defeats split-horizon tricks).
- **Public-IP test** (`_is_public_ip`) rejects: private (`10/8`, `172.16/12`,
  `192.168/16`, `fc00::/7`), loopback (`127/8`, `::1`), link-local (`169.254/16`,
  `fe80::/10` — this is the cloud-metadata range), CGNAT (`100.64/10`), multicast,
  reserved, unspecified (`0.0.0.0`, `::`). Uses `ipaddress`.

### 2. Manual, per-hop-validated redirects

`follow_redirects=False`. A new `_safe_get(client, url)` loops ≤ `MAX_REDIRECTS` (3):
`validate_url(url)` → GET → if 3xx with `Location`, resolve it against the base and
**re-validate before the next hop**. `evil.com → http://169.254…` is caught because the
redirect target fails the scheme + IP checks. `file://` redirect targets fail the scheme
check. DNS resolution runs in a thread executor so it doesn't block the async gather.

### 3. Fail-closed behaviour

A blocked URL is **skipped with a logged warning** — the fetch returns whatever safe
pages resolved (usually nothing for a poisoned row). Upstream, "no fetchable sources"
already raises `ResearchError`, so a poisoned lead lands in `research_failed` and never
sends. No exception is surfaced to the API caller (the CSV importer isn't the attacker's
feedback channel). Timeout stays 15s.

### 4. Known residual (documented, not silently ignored)

Between "resolve + validate" and "httpx connects (which re-resolves)" there is a
DNS-rebinding TOCTOU window: a hostile resolver could return a public IP to our check
and a private IP to httpx's connection. Full closure requires pinning the connection to
the validated IP while keeping SNI/cert validation for the hostname — a heavier
transport-level change. **Proposed:** ship the resolve-and-validate guard now (closes
100% of the finding's stated vectors: literal-IP, port, scheme, redirect-to-private),
and log the rebinding residual in `findings/06` as a candidate for a hardening pass. In
this app the fetched bytes only feed the grounded validator, so the residual is
read-only probing, not exfiltration. Flagging for the gate rather than deciding alone.

## Tests

**Unit — `tests/unit/test_fetch_ssrf.py`** (pure, no network; `getaddrinfo` monkeypatched):
- `_is_public_ip`: true for `8.8.8.8`, `1.1.1.1`, a public IPv6; false for `10.0.0.1`,
  `127.0.0.1`, `169.254.169.254`, `192.168.1.1`, `172.16.0.1`, `::1`, `fc00::1`,
  `0.0.0.0`, `100.64.0.1`, `224.0.0.1`.
- `validate_url` rejects: `http://x`, `file:///etc/passwd`, `ftp://x`,
  `https://169.254.169.254/`, `https://127.0.0.1/`, `https://[::1]/`,
  `https://localhost:6379/` (port), and a host that resolves to a private IP
  (monkeypatched). Accepts a host that resolves to a public IP (monkeypatched) and a
  literal public IP.

**Adversarial — `tests/adversarial/test_fetch_ssrf_attacks.py`** (predict-then-run,
offline via a fake transport/client):
- The four named vectors as end-to-end `_safe_get` cases: literal metadata IP,
  `localhost:6379`, a `file://` redirect target, and `evil→http://169.254…` redirect
  (fake client returns the 302). Each must be blocked/skipped, none fetched.
- `MAX_REDIRECTS` bound: a redirect chain longer than 3 stops.
- Confirm a normal public host with an HTML body still succeeds (fake client).

The existing research tests must pass unmodified. Suite green, 0 skipped, Postgres up.

## Open questions for approval

1. **DNS-rebinding residual** — ship the resolve-and-validate guard now and log the
   rebinding TOCTOU as a documented residual (my proposal), or block M0.5 on a full
   pin-to-IP transport rewrite? I propose the former.
2. **Port allowlist = {443, default}** — this also blocks a legitimate company site
   served on `:8443` etc. Acceptable for a research fetcher? I propose yes (strict).
3. **Blocked URL = skip + log** (fail-closed, lead ends `research_failed`) vs. surfacing
   a distinct error/flag on the lead so an operator sees "this domain was refused as
   unsafe." I propose skip + log for now; a lead-level flag can come with the M1.3 leads
   UI.

## Implementation order

1. `validate_url` / `_is_public_ip` / `UnsafeURL` + unit tests (pure first).
2. `_safe_get` manual-redirect loop; wire into `fetch_company_text`; executor for DNS.
3. Adversarial suite (offline fake client) for the four named vectors + redirect bound.
4. Docs: README GDPR/security note is untouched; add an SSRF line to the security
   section of APPLICATION_OVERVIEW; A2 → resolved; `findings/06-ssrf.md` with the
   rebinding residual.
